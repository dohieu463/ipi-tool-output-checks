# Methods and Results (hand-off for the paper)

Status: complete. Every number below is regenerated by
`analyze_seeds.py` / `analyze.py` from `results/`; nothing is hand-computed.
All experiments ran from 2026-11-01 to 2026-11-02.

---

## 1. Setup

| Item | Value |
|---|---|
| Benchmark | AgentDojo v1.2.2, suites `slack` (21 user tasks) and `banking` (16 user tasks) |
| Attack pairs | 249 per configuration (slack 105 + banking 144) |
| Agent model | `gpt-4o-mini-2024-07-18`, temperature 0.0, no max-token cap |
| Checker model | same as agent unless stated otherwise |
| Seeds | 3 independent runs for the main attack (`--seed 1/2/3`); 2 runs for the generalization attack |
| Hardware | 12-core CPU, no GPU; DeBERTa runs on CPU |
| Cost | ≈ $28.3 of OpenAI usage in total |

Each configuration runs a benign phase (37 tasks) and an attacked phase (249 pairs). The
check sits between tool execution and the agent LLM: it sees only the tool output and the
user task.

Defenses: `none`, `spotlighting_with_delimiting` (AgentDojo), `repeat_user_prompt`
(AgentDojo), `regex_detector` (ours), `transformers_pi_detector` (AgentDojo DeBERTa
`protectai/deberta-v3-base-prompt-injection-v2`, threshold 0.5), `llm_detector` (ours),
`llm_sanitizer` (ours). A separate ablation adds `transformers_line_filter` (same DeBERTa,
line-level removal instead of whole-output replacement).

Attacks: `important_instructions` (AgentDojo's standard attack) and `casual_note`
(ours: the same goal hidden in an ordinary "P.S." line that avoids injection vocabulary).

## 2. Metrics

- **BU** — benign utility: task success without an attack.
- **UA** — utility under attack.
- **ASR** — attack success rate: the agent performed the attacker's goal.
- **Benign flag rate** — false-positive rate of a check on clean tool outputs.
- **USD/task**, **tokens/task**, **seconds/task** — measured in the benign phase.
- **p** — exact McNemar on the paired `(suite, user task, injection task)` outcomes.
- Confidence intervals — Wilson 95% (single run); across seeds we report mean ± sample sd.

Cost on OpenAI is estimated from token counts using a price table in `ipi_eval/usage.py`,
because the API does not return a price. On the OpenCode gateway the reported
`usage.opencode.allowance` is used instead.

## 3. Results — main attack (`important_instructions`, 3 runs)

| Defense | BU % | UA % | ASR % | p vs none (per run) | Benign flag % | USD/task |
|---|---|---|---|---|---|---|
| No defense | 71.2 ± 3.1 | 50.3 ± 3.5 | 54.8 ± 1.2 | – | – | 0.00067 |
| Spotlighting (delimiters) | 64.0 ± 4.1 | 49.9 ± 1.7 | 52.2 ± 1.2 | 0.31 / 0.14 / 1 | – | 0.00064 |
| Repeat user prompt | 64.0 ± 1.6 | 44.0 ± 0.6 | 21.8 ± 1.9 | 7e-26 / 1e-22 / 2e-16 | – | 0.00423 |
| Regex detector | 66.7 ± 1.6 | 24.2 ± 3.8 | 0.0 ± 0.0 | 6e-42 / 6e-42 / 2e-40 | 0.0 | 0.00064 |
| DeBERTa (block output) | 36.0 ± 3.1 | 30.4 ± 2.5 | 10.6 ± 0.2 | 1e-32 / 3e-31 / 5e-29 | 86.1 ± 2.3 | 0.00242 |
| LLM detector | 62.2 ± 0.0 | 24.0 ± 5.2 | 0.0 ± 0.0 | 6e-42 / 6e-42 / 2e-40 | 3.6 ± 0.2 | 0.00079 |
| **LLM sanitizer** | 58.6 ± 1.6 | **49.5 ± 0.6** | **0.0 ± 0.0** | 6e-42 / 6e-42 / 2e-40 | 14.9 ± 1.8 | 0.00092 |

Single-run detail (seed 1): tokens and latency per task in the benign phase —
`none` 3.95k / 4.6 s; spotlighting 3.73k / 4.6 s; repeat-user-prompt 25.96k / 18.7 s
(**+557% tokens**); regex 3.93k / 4.6 s; DeBERTa 16.72k / 18.1 s (+323%);
LLM detector 5.25k / 7.7 s (+33%); LLM sanitizer 5.70k / 9.8 s (+44%).

## 4. Results — generalization (`casual_note`, 2 runs)

Reported as run A / run B (ASR % / UA %):

| Defense | Run A | Run B |
|---|---|---|
| No defense | 35.3 / 52.6 | 35.3 / 55.4 |
| Regex detector | **36.1** / 52.6 | **34.9** / 54.6 |
| DeBERTa (block output) | 2.0 / 24.9 | 2.0 / 24.1 |
| LLM detector | 0.0 / 23.7 | 0.0 / 21.3 |
| LLM sanitizer | 0.0 / 47.4 | 0.0 / 48.6 |

The quieter attack reproduces at the same rate (35.3% both times) and defeats the regex
detector entirely (`p = 1.0` in both runs), while both LLM-based checks still reach 0% ASR.

## 5. Detection-policy ablation (DeBERTa)

Same classifier, two policies. Single run, compared against the same-day undefended
baseline (this is an exploratory comparison, not a 3-seed estimate).

`important_instructions`:

| Policy | BU % | UA % | ASR % | Benign flag % |
|---|---|---|---|---|
| No defense | 62.2 | 49.0 | 56.2 | – |
| DeBERTa, replace whole output | 32.4 | 29.3 | 10.8 | 83.3 |
| DeBERTa, drop flagged lines | 54.1 | **53.4** | **1.6** | 36.5 |

`casual_note`:

| Policy | BU % | UA % | ASR % | Benign flag % |
|---|---|---|---|---|
| No defense | 67.6 | 52.6 | 35.3 | – |
| DeBERTa, replace whole output | 32.4 | 24.9 | 2.0 | 89.2 |
| DeBERTa, drop flagged lines | 56.8 | **46.2** | 2.4 | 35.2 |

Changing only the policy raises UA by 22–24 points and, on the main attack, also lowers
ASR (10.8 → 1.6). The utility loss of the DeBERTa configuration is therefore attributable
to whole-output replacement, not to the classifier's false positives alone.

## 6. Checker-capacity control

Same agent (`gpt-4o-mini`), stronger checker (`gpt-4o`), 249 pairs:

| Checker | LLM detector UA | LLM sanitizer UA | ASR |
|---|---|---|---|
| gpt-4o-mini (3-run mean) | 24.0 ± 5.2 | 49.5 ± 0.6 | 0 / 249 |
| gpt-4o | 22.5 | 50.6 | 0 / 249 |

No change. The detector's utility loss is a property of its blocking policy, not of
checker capability.

## 7. Findings

1. **Prompt-level defenses do not defend.** Spotlighting is statistically
   indistinguishable from no defense in all three runs (52.2% vs 54.8% ASR). Repeating the
   user prompt reduces ASR to 21.8% but costs **+531% tokens** and 4× latency.
2. **Checks can zero the attack; only sanitization keeps the agent usable.** Regex, the
   LLM detector and the LLM sanitizer all reach ASR 0/249 (95% CI upper bound 1.5%). But
   the detector halves utility (UA 24.0) because a flagged output is replaced entirely,
   whereas the sanitizer deletes only the hostile span and holds UA at 49.5 ± 0.6 against
   a 50.3 ± 3.5 baseline.
3. **The blocking policy, not the classifier, causes most of the utility loss.** The
   same DeBERTa with line-level removal recovers 22–24 points of UA and even improves ASR.
4. **Generalization separates the checks.** The regex detector is a template matcher: it
   is perfect on `important_instructions` and useless on `casual_note` (34.9–36.1% ASR,
   p = 1). Both LLM checks still reach 0%, at a 3–7× lower false-positive rate than
   DeBERTa.

## 8. Threats to validity

- **One agent model.** All conclusions are for `gpt-4o-mini-2024-07-18`. The screening
  phase showed that several current open-weight models (GLM-5.3-Flash, MiniMax-M3,
  DeepSeek-V4.1-Flash, MiMo-V2.6-Flash) resist this attack almost completely (ASR 0–3%),
  which would create a floor effect; that screening is not part of the reported grid.
  It is, however, itself a relevant observation for the discussion.
- **Seeds are best-effort.** OpenAI's `seed` parameter does not guarantee determinism.
  We report the measured between-run sd rather than claiming reproducibility.
- **Cost is estimated** from token counts, not read from a bill.
- **The regex detector overlaps the `important_instructions` template** by construction
  (documented in the source). Its ASR 0% is an optimistic bound; the `casual_note` result
  is the honest test, and there it fails.
- **The ablation is a single run** against a same-day baseline, not a 3-seed estimate.
- **DeBERTa is used off the shelf** at threshold 0.5, with no tuning on tool outputs;
  a tuned threshold could change its false-positive rate.
- **`casual_note` has two runs**, not three.
- **The checks are hand-written prompts**, not optimized or ensembled; a stronger
  sanitizer prompt might recover more utility.
- **Pairwise dependence.** Tasks share templates and environments, so McNemar p-values
  should be read as within-benchmark comparisons, not population-level guarantees.

## 9. Reproduction

```bash
uv venv --python 3.12 .venv && source .venv/bin/activate
uv pip install --index-url https://download.pytorch.org/whl/cpu "torch>=2.2.1"
uv pip install -r requirements.txt
cp .env.example .env    # fill OPENAI_API_KEY

python scripts/preflight.py
RESULTS_DIR=results/seed-1 LOGDIR=runs/seed-1 TAG=seed1 SEED=1 \
  ATTACKS="important_instructions casual_note" MAX_PARALLEL=4 bash scripts/run_batch.sh
RESULTS_DIR=results/seed-2 LOGDIR=runs/seed-2 TAG=seed2 SEED=2 \
  ATTACKS="important_instructions" MAX_PARALLEL=2 bash scripts/run_batch.sh
RESULTS_DIR=results/seed-3 LOGDIR=runs/seed-3 TAG=seed3 SEED=3 \
  ATTACKS="important_instructions" MAX_PARALLEL=2 bash scripts/run_batch.sh

TAG=ablation RESULTS_DIR=results/ablation LOGDIR=runs/ablation \
  MAIN_DEFENSES="transformers_line_filter" GEN_DEFENSES="transformers_line_filter" \
  MAX_PARALLEL=2 bash scripts/run_batch.sh
TAG=checker RESULTS_DIR=results/checker-gpt4o LOGDIR=runs/checker-gpt4o \
  CHECKER_MODEL=gpt-4o MAIN_DEFENSES="llm_detector llm_sanitizer" \
  ATTACKS="important_instructions" MAX_PARALLEL=1 bash scripts/run_batch.sh

bash scripts/finalize.sh
```

## 10. Suggested paper skeleton

1. **Intro** — tool outputs are an attack surface; checks are the practical defense, but
   their utility and cost are unmeasured.
2. **Method** — the 8 configurations, the two attacks, the metrics, the paired design.
3. **Results**
   - prompt-level defenses fail (§3);
   - checks reach ASR 0 but only sanitization preserves utility (§3);
   - policy ablation explains the utility loss (§5);
   - generalization separates template matching from semantic checks (§4);
   - checker-capacity control rules out "weak checker" (§6).
4. **Cost** — tokens/latency/USD per task, with repeat-user-prompt as the cautionary case.
5. **Limitations** — §8.
6. **Artifact** — `results/`, `runs/`, scripts, seeds.
